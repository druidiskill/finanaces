# Finances Bot

Telegram-бот на aiogram для учета доходов и расходов с записью в Google Sheets. Подходит для совместного учета двух пользователей, работающих с общей таблицей.

## Возможности
- Учет доходов и расходов через inline-кнопки.
- Категории и подкатегории любой вложенности (берутся из истории таблицы).
- Сводка: чистая прибыль (Доходы - Расходы).
- Раздел "Цели" с этапами/подэтапами, статусами и комментариями.

## Требования
- Python 3.11+ (рекомендуется 3.12).
- Доступ к Google Sheets через service account.

## Установка
```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## Конфигурация
1) Создайте service account в Google Cloud и скачайте JSON-ключ. Файл должен называться `google.json` и лежать в корне проекта.
2) Создайте `.env` по примеру `.env.example`.
3) Убедитесь, что таблица доступна сервисному аккаунту (поделитесь таблицей на email service account).

Минимальный набор переменных в `.env`:
- `BOT_TOKEN` — токен Telegram?бота.
- `ALLOWED_USER_IDS` — два chat_id через запятую (например: `123,456`).
- `USER_NAME_MAP` — сопоставление chat_id > имя пользователя (например: `123:Борис,456:Анна`).
- `GOOGLE_SHEET_ID` — ID таблицы Google Sheets.
- `GOOGLE_WORKSHEET_NAME` — имя листа доходов/расходов.
- `GOALS_WORKSHEET_NAME` — имя листа целей.
- `GOOGLE_SERVICE_ACCOUNT_FILE=google.json` — путь к файлу service account.

## Как работает учет доходов и расходов
- Выбор выполняется через inline?кнопки (без текстовых команд).
- Валюта — рубли, формат суммы: `1000,00`.
- Категории и подкатегории подгружаются из истории записей в таблице.
- После выбора категории можно создавать подкатегории до любого уровня и завершить выбор кнопкой "Готово".
- В комментариях есть кнопка "Без комментариев".
- Пользовательские сообщения после обработки удаляются (для чистоты чата).

## Структура листов Google Sheets

### Лист доходов/расходов
Колонки:
1) `date` — дата в формате `DD.MM.YYYY` (например, `21.01.2026`).
2) `kind` — тип операции на русском: `Доход` или `Расход`.
3) `amount` — сумма в формате `1000,00` (разделитель дробной части — запятая).
4) `category_path` — путь категории, например `Еда > Продукты > Овощи`.
5) `comment` — комментарий пользователя.
6) `user_name` — имя пользователя без кавычек.

### Лист "Цели"
Колонки:
- `id` — уникальный идентификатор записи.
- `parent_id` — родительская цель/этап (если есть).
- `path` — полный путь: `Цель > Этап > Подэтап`.
- `type` — тип записи: `goal` или `step`.
- `title` — название цели/этапа.
- `status` — статус: `todo`, `in_progress`, `done`.
- `due_date` — дата, к которой нужно выполнить: `DD.MM.YYYY`.
- `created_at` — дата создания: `DD.MM.YYYY`.
- `updated_at` — дата последнего изменения: `DD.MM.YYYY`.
- `order` — порядок сортировки в списке.
- `note` — история комментариев.
- `owner` — пользователь, создавший запись.

## Раздел "Цели" — логика интерфейса
- При входе в раздел отображается список целей и кнопки "Добавить цель" и "Назад".
- При выборе цели отображаются этапы (по срочности) и кнопки "Комментарий" и "Назад".
- При выборе этапа отображаются подэтапы (если есть) и кнопки "Комментарий" и "Назад".
- Если подэтапов нет, показываются кнопки:
  - "Делегировать"
  - "В расписание" (пока в разработке)
  - кнопка статуса (с эмодзи)
  - "Комментарий"
- Если все подэтапы выполнены, у этапа появляется эмодзи выполненности и он уходит в конец списка.
- Если все этапы выполнены, у цели появляется эмодзи выполненности.
